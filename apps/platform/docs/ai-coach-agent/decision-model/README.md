# FormPilot 比赛版可选决策模型 fp-coach-ranker v1.0.0

历史基线研究日期：2026-11-07。本文件记录手工权重排序器及描述符研究，当前训练模型见 [MODEL_REPORT.md](MODEL_REPORT.md)。

**一句话结论：** 本轮没有训练新权重，也没有复用 StartLux 权重。交付的是一个**确定性、受约束、可解释的排序模型**：特征来自画像、可信目录和由参考姿态轨迹实测的动作描述符，安全门禁和 P0 规则服务保持不变。正式启用开关默认 `off`。

| 验收层级 | 判定 |
| --- | --- |
| 研究验证 | **通过（限定）**：路线比较、数据/许可核验、描述符与人工标签的独立来源一致性、预注册规则均有证据 |
| 离线技术验证 | **通过**：全画像空间对照、冻结 persona、故障注入、延迟/体积、新增 33 项测试全部通过 |
| 产品真实验收 | **未进行，不判 PASS**：没有真人、专家标签、Web 接线或浏览器 E2E |

## 1. 技术路线选择

| 方向 | 结论 | 依据 |
| --- | --- | --- |
| A 继续微调 StartLux | **放弃** | 冻结 LoRA 的任务是 Isleward 三种肩部动作的下一回合六分类干预，不是功法/章节/游戏排序；FormPilot 请求在 forward 前就返回 `PROFILE_NOT_IN_MODEL_SCOPE`。训练数据为 108/24/36 条 synthetic 作者标签（`pending_domain_expert`）。权重为 CC BY-NC 4.0，没有商业许可，不能进入比赛提交包。4B 模型冷启动约 274 s，P95 约 667 ms（热态），与同步 Web 推荐不匹配 |
| B StartLux 只管局部游戏难度，另建推荐模型 | **前半部分保持现状，不在本仓库实施** | StartLux 继续作为 Isleward 内的非商业研究（D1–D3 PR 不动）。FormPilot 没有已批准的难度控制器，也没有 FP 域 profile |
| C 分类 / LTR / 树模型 | **排序不训练，只做了一个小实验** | 没有“画像→内容”的独立标签：没有真实用户、没有专家标注；Isleward 的 `decision_eval` 数据 是 Isleward 肩部难度测试集，且标记 `exclude_from_training`。在规则或作者标签上训练，最多只能复现它们。唯一做过的学习实验：用 3 个功法学习“描述符→注意标签”阈值，再在第 4 个功法上检验（leave-one-programme-out）。κ 最多提升约 0.1，没有改变任何使用决定 |
| **D+ 规则排序/特征/可解释性优化（选定）** | **实施** | 目录只有 68 项、画像空间可以穷举（89,280 个），因此可以全量验证。新增特征来自项目自有的标准示范参考轨迹（可追溯、可复算）。浏览器内同步运行，零依赖、无 GPU、可回退 |

## 2. 模型结构

```
CoachWebRequest ──► P0 getCoachWebRecommendation（不变） ──► rules（始终保留，作为回退）
        │                       │ status 必须为 ready（error / profile_required / safety_hold 时模型不运行）
        ▼                       ▼
 宿主 options（mode / availability，仅可信宿主代码提供）
        ▼
 完整性检查：目录指纹 + 描述符版本/章节集 ──失败──► rules（INTEGRITY_MISMATCH）
        ▼
 硬约束候选池：P0 同款安全过滤（verified、受限画像排除 caution、章节须有 href）
             + 实测注意项并集（只增不减） + 宿主可用性快照（只删不加）
        ▼
 效用打分（可加和）→ 贪心选取（主要匹配优先、覆盖增益、多样性）→ 统一优先级
        ▼
 独立输出守卫（guard.ts，不复用排序器的候选池代码）──违规──► rules（OUTPUT_GUARD_REJECTED）
        ▼
 off：不运行；shadow：运行但 active=rules；active：受控演示，active=模型结果
```

效用 = 3.0×部位相关度（目录标签 F1）+ 1.5×训练方向一致度（画像需求向量）+ 1.0×（实测活动幅度 − 0.5）− 0.3/0.6×负荷指数 + 证据加分（上限 0.6）；贪心阶段另加 1.2×新覆盖部位数，并减去 0.6×与已选条目的最大相似度。权重是有文档说明的工程取值，不是拟合得到的；每个推荐项都附有逐项 `contributions`（数值、权重、说明、来源），合计等于 `utility`（由测试校验）。

画像需求映射（v1，待领域审核）区分了 P0 中合并的 mobility 与 upper_limb，并让 stiffness（P0 中不产生任何作用）进入排序。这些映射是训练方向的工程建议，不是处方。

### 参考轨迹实测描述符

`scripts/decision-model/extract-motion-descriptors.ts` 从 4 套标准示范视频的姿态轨迹（10 fps，MediaPipe Pose Lite，仓库内文件，按 SHA256 固定），按章节时间窗计算过顶、俯身、单腿、转体、深屈膝、近地支撑 6 类帧标志，以及肩、上肢、颈、躯干、下肢五个部位的活动幅度。阈值在与目录标签比较之前就已预注册（`descriptor-config.json`，冻结哈希 `6e95c22d…`）。提取器从不读取目录标签，因此后续一致性比较属于两个独立来源之间的比较。

60 章中 59 章数据可靠（tjq-24 时间窗只有 3 s）。与人工目录标签的一致性，以及按预先声明的规则 U1/U2 得出的使用决定：

| 通道 | 精确率 / 召回率 / κ | 使用 |
| --- | --- | --- |
| 俯身 bending | 0.67 / 0.86 / 0.71 | 受限画像的保守并集 |
| 平衡 balance（仅单腿；提踵不可测） | 1.00 / 0.30 / 0.24 | 保守并集 |
| 过顶 overhead | 0.44 / 0.92 / 0.44 | 仅审计：14 章实测有过顶而目录未标，交人工复核（如 wqx-10 鸟飞、wqx-close 引气归元、bdj-6 两手攀足） |
| 转体 twist / 支撑 weight_bearing | 0.29 / 0.50 / 0.10；0.20 / 1.00 / 0.31 | 仅审计（整体转身与“手到脚面”会误触发） |
| 部位活动幅度 AUC | 上肢 0.86、躯干 0.75、下肢 0.87；肩 0.61、颈 0.46 | 前三个部位用于排序细化，肩、颈只用目录标签 |

当前目录下，保守并集**没有新增任何排除**（实测到的俯身/单腿章节本来都已带注意标签）。受限画像可用的 6 个章节中有 5 个数据可靠，实测均未触发任何注意类标志（tjq-23 只有深屈膝负荷描述符，约 2.2 s；tjq-24 无法验证）。并集作为未来新增目录内容的结构性保护保留。

与 P0 相比，模型结果 57.5% 发生变化，27.2% 只调整顺序，15.3% 完全相同。迭代过程：第 1 轮完整覆盖率下降到 94.3%（受限且选择躯干的画像漏掉了 tjq-23）。第 2 轮把覆盖增益改为按新覆盖部位计数后，恢复到 100%。只在开发集与画像空间上迭代；冻结 persona 只运行了 1 次。

**故障与回退**（每类 604 个画像，全部按预期回退，active 结果与 P0 逐字段相同）：默认 off、shadow、未知 mode、排序器抛错、注入 caution 章节、重复条目、虚构 id、冒称训练权重、未知可用性 id、目录漂移；另外，排序器忽略可用性时守卫拒绝 604/604。携带 modelOutput、evidence 或 source=startlux 的请求一律返回 `REQUEST_INVALID`。

**性能**（开发机单线程 Node、热态，22,320 次）：P0 p50 0.051 ms / p95 0.122 ms；适配层 off 0.099 / 0.230 ms；active 0.553 / 1.145 ms（最大 3.26 ms，含一次 P0 调用）；不使用 GPU/VRAM，也不发网络请求。浏览器 ESM 体积：P0 服务 42.7 KB min / 11.9 KB gzip；含 P0 的模型入口 105.2 KB / 26.5 KB，即增加约 62.5 KB / 14.6 KB（主要是描述符 JSON）。

## 4. 安全、许可与泛化限制

- 不做诊断、不提供处方或剂量；排序只能在既有目录内进行，不能生成新动作。风险暂停、受限过滤和 P0 门禁都没有修改；模型只能让候选池变得更严格。
- 没有真实用户数据、专家标签或疗效证据。所有评测都是 synthetic 或规则一致性评测，不能宣称真实推荐质量或康复效果。冻结 persona 与模型出自同一作者（CC），存在作者偏差。
- 描述符来自单一示范者的二维姿态（MediaPipe Lite），是工程代理，不是关节活动度或负荷测量。提踵不可测，颈部与肩部通道没有通过 U2。
- 游戏没有轨迹描述符，只用目录标签。四个游戏均为独立应用（href=null），推荐不代表可以启动。
- 历史与报告：v1 的接口与 P0 一致（rules 模式无证据；synthetic 模式使用固定样例并标注 synthetic）。真实历史的可信接入仍是后续工作。
- 许可：没有使用、复制或分发 StartLux 权重或任何 CC BY-NC 资产；描述符来自仓库内既有参考轨迹（与跟练评分同一用途）。MobiPhysio/REHAB26 测试集未读取用于训练。
- 目录任何改动都会改变指纹，模型随即自动回退到规则，直到重新运行审计与评测并更新 `VALIDATED_CATALOGUE_FINGERPRINT`。

## 5. 复现

通过根目录 `scripts/submission/run_ts.mjs` 运行下列 TypeScript 脚本，方法见[训练复现](../../../../../docs/submission/TRAINING_REPRODUCTION.md)。下列 `node $VN` 是原研究命令中的 vite-node 占位。

```bash
node $VN scripts/decision-model/extract-motion-descriptors.ts        # 重新生成描述符（确定性）
node $VN scripts/decision-model/audit-descriptors.ts <out.json>      # 描述符与目录标签一致性 + LOPO
node $VN scripts/decision-model/evaluate.ts --out <dir> --personas dev  # 开发集；frozen 仅在版本冻结后运行一次
node node_modules/vitest/vitest.mjs run tests/coach-decision-model.test.ts tests/coach-decision-model-descriptors.test.ts
```

Web 接线说明见 [WEB_INTEGRATION.md](WEB_INTEGRATION.md)。
