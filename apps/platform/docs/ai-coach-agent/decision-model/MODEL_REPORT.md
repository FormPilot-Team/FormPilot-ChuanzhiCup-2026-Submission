### 0.1 模型实际能做什么、不能说什么

- **能做**：对一个自述画像（加可选的本机训练历史与最近报告），在安全筛选后的约 12 个候选内，按“与单一 AI 标注者在 72 个合成场景上的判断相一致”的方式排序，并给出可读理由；超出训练范围或把握不足时弃权，交回规则结果。
- **证据层级**：
  1. 工程与安全行为：离线验证，可复现（§5、§7）。
  2. 排序质量：只有与 AI 标签的一致性。冻结测试上 NDCG@5 的优势不显著，CI 跨 0。
  3. 人工一致性：0 条人工标签。
  4. 真实用户、专家或临床：没有任何证据。
- **不能说**：“比规则推荐更好”“经人工 / 专家验证”“个性化效果已证实”“有康复或医疗效果”。可以说：“训练的偏好排序模型（实验性，AI 标注训练，项目负责人已审阅标签）”“离线技术验证通过”“普通构建关闭；竞赛构建经负责人批准启用，弃权或异常时回退到规则”。

## 1. 架构与版本

```
Web ──► recommendCoachDecision(input, { mode })            契约 fp-coach-decision/v1（冻结），同步、浏览器内、无网络
  ▼ 严格校验输入：未知字段 / 目录外 id / 越界 / 未来时间 → INPUT_INVALID（规则）
  ▼ Agent Web P0 规则服务（不变；OFF 时就是它的输出；任何回退都回到它）
  ▼ 前置门禁：画像不全 / 风险暂停 → 不调用模型
  ▼ 发布完整性：权重指纹、M1 内容表指纹、目录指纹与发布清单一致，否则不运行模型
  ▼ 安全候选池（规则）：P0 同款过滤 + 实测注意项并集 + 可用性（只删不加）
  ▼ 第一阶段检索（规则，K=12）：P0 结果 + PR #49 结果 + PR #49 效用补足
  ▼ 第二阶段 fp-cdm-m2（训练）：111 个特征（P 画像×内容 / H 历史×内容 / R 报告×内容，含 M1 动作感知特征）→ 线性成对偏好分
  ▼ 校准：Platt → 适配概率；成对温度 → 首选置信度
  ▼ 弃权：最高适配概率 < τ，或首选候选的特征超出训练范围（+25%）→ ABSTAIN（规则）
  ▼ 独立 Guard（自行重算安全池，不修复）→ 违规 → 规则
  ▼ 模式门：off（默认）规则 / shadow 规则展示 + 模型排序 / active 模型展示（实验性权重需 allowExperimentalModel）
```

**排序由训练模型完成**：最终顺序、推荐组合、适配概率与解释全部来自 M2。规则只负责安全筛选、候选约束（检索与展示上限）、可用性与异常兜底。

## 3. M1 内容理解模型

- 任务：用窗口级姿态特征预测章节的部位标签与注意标签。章节得分 = 窗口概率的均值（部位）或 90 百分位（注意项），聚合方式预先声明。
- 协议：**嵌套按功法留一**。外层留出整套功法；内层只在其余 3 套功法上做留一，选择特征集（v1 / v2）、模型族（LR / HGB / ExtraTrees）和超参数。
- 结果（9 个可学习标签的宏平均 AUC）：
  - M1 v1.1（嵌套）**0.777**（部位 0.748，注意项 0.813）；v1.0（HGB，非嵌套）0.761；PR #49 手工描述符 0.737；差值的 bootstrap CI 为 [−0.020, 0.091]。
  - 按留出功法：八段锦 0.785｜太极拳 **0.606**（最难）｜五禽戏 0.811｜易筋经 0.836。
  - 各标签：肩 0.50，颈 0.83，上肢 0.79，躯干 0.75，下肢 0.87，过顶 0.77，平衡 0.89，转体 0.68，俯身 0.91；weight_bearing 只有 1 个正例章节，不可学习。
- 负结果：新增的 28 个 v2 姿态特征没有带来提升（最好的 v2 配置 0.743，v1 为 0.791），未采用。
- 鲁棒性（只扰动测试特征，5 个种子）：无扰动 0.791｜噪声 0.1 / 0.25 / 0.5 SD：0.792 / 0.779 / 0.755｜特征缺失 20% / 40%：0.751 / 0.680。
- 部署方式：目录固定，M1 的输出以内容表形式随发布绑定（每章的值来自没见过该功法的模型），浏览器只读该表，不运行姿态模型。

## 4. M2 偏好排序模型

### 4.1 训练与选择

- 特征 111 个（P 95 / H 11 / R 5），只保留在同一用户的候选之间变化的特征；缺失的历史或报告对应特征为 0。
- 在 18 个开发族上做 6 折分组交叉验证。预先声明只选线性模型（浏览器可运行），HGB 只作离线对照。选中 pairwise LR，C = 0.01。
- 校准：成对温度 T = 0.90；Platt 只在开发集 OOF 上拟合；弃权阈值 τ = 0.842（top-1 精度 ≥ 0.85）。
- 流水线对照：植入的随机隐藏信号能学到（测试 NDCG@5 0.88）；随机标签学不到（0.51），未发现泄漏。
- 本阶段用同一流程重新拟合，系数与发布权重完全一致（`refitMatchesRelease: true`）。

### 4.2 冻结测试（单次，6 个族 / 18 个场景，AI 标签）——与规则、PR #49 的公平对照

三者使用相同候选池、相同标签和相同指标；规则与 PR #49 收到相同的历史 / 报告信息。

| 系统 | NDCG@3 | NDCG@5（95% CI） | P@3 | R@5 | 成对准确率 |
| --- | --- | --- | --- | --- | --- |
| 规则 P0 | 0.736 | 0.819（0.738–0.886） | 0.722 | 0.669 | 0.707 |
| PR #49 手工权重 | 0.770 | 0.797（0.723–0.849） | 0.759 | 0.625 | 0.732 |
| **fp-cdm（P+H+R）** | 0.811 | **0.868**（0.738–0.959） | 0.889 | 0.763 | **0.873** |

模型 − P0 的 NDCG@5 差值 CI 为 [−0.024, 0.122]，模型 − PR #49 为 [−0.090, 0.174]，NDCG 优势**不显著**。成对准确率的差距较大（0.873 对 0.707 / 0.732），但没有做区间估计；测试只有 18 个场景，标签来自训练标签的同一 AI 标注者，不能据此说模型优于规则。测试集只评测过这一次，收尾阶段也没有为补算区间而再次使用它。

### 4.3 开发集研究（只用开发族；冻结测试不参与）

- 特征组逐级加入（NDCG@5）：规则 P0 0.810｜PR #49 0.774｜学习的 3 个基础特征 0.788｜只用交叉特征 0.855｜画像×内容但不含 M1 0.876｜加入 M1 0.890｜+历史 0.894｜+历史+报告 **0.897**。
- 学习曲线：训练族数 3 → 15 时，NDCG@5 从 0.827 升到 0.897，仍在上升。
- 标签噪声：训练标签有 10% / 20% / 30% 被 ±1 扰动时，NDCG@5 为 0.879 / 0.871 / 0.880。
- 校准：ECE 0.032，Brier 0.161。
- 跨功法排序（训练时去掉某功法，再为该功法内容排序）：八段锦 0.951（规则 0.926 / PR #49 0.950）、太极拳 0.957（0.953 / 0.916）、五禽戏 1.000（0.938 / 1.000）、易筋经 0.962（0.941 / 0.928）。
- 采纳规则（预先声明）：用 M1 v1.1 特征的 M2 在开发集上为 0.883，低于 0.897 − 0.005，**未采纳**。

### 4.5 行为探针（I4，发布引擎，合成探针用户，描述性）

输入与输出逐条保存在 `artifacts/integration/probes.json`。

- **改变训练目标**（上肢功能练习 → 其他目标）：肩颈活动时模型对共同候选的排序不变（τ = 1.0），推荐组合只换了一个游戏；日常锻炼时候选集合变化较大（组合重合 0.43，τ = 0.94）。目标主要通过候选检索影响结果，与 §4.4“目标交叉无增益”一致。康复辅助意向会让画像进入受限安全池，变化来自安全规则而不是模型。
- **改变关注部位**：9 组部位中 6 组给出模型推荐，部位命中率与规则、PR #49 相同；只选“上肢”“下肢”或“上肢 + 下肢”时适配概率不足（首选 0.73–0.82 < τ 0.842），模型弃权回退规则。全画像空间上模型的部位覆盖率最高（§4.6）。
- **不同训练阶段（同一用户）**：新用户 → 第 1 周 → 第 2 周 → 第 4 周，与新用户排序的 τ 为 1 → 0.89 → 0.75 → 0.75，推荐中新内容占比 1 → 1 → 0.8 → 0。**历史越多，模型越倾向衔接已练内容**；这是 AI 标签学到的偏好，是否合理需要人工判断。
- **最近报告**：报告主要把“报告所指的那一章”重新排到前面（第二式 4 → 1，第一式 9 → 1 或 5，韦驮献杵 2 → 1）；按方向看，同方向其他内容没有整体提前。
- **风险**：三种风险全部安全暂停，模型未执行。
- **分布外**：关注 4 个部位（肩、颈、上肢、下肢）→ `OUT_OF_DISTRIBUTION`（`x_region_overlap`），3 个部位正常排序。
- **近期练习**（已知局限）：首选章节 0–2 天内刚练过 → `h_recency_this` 超出训练范围 → 弃权回退规则；3 天及以上正常排序。原因：合成训练场景中被练过且进入候选的章节都在 4–20 天前。
- **输入扰动**：第 2 周用户的分数 ±5、时间 ±1 天、次数 ±1（200 次），Kendall τ 中位数 1.0（5% 分位 0.97），首选与推荐组合 100% 不变。
- **研究变体**（与发布模型的 τ，6 个画像）：去掉画像交叉 0.21–0.58（变化最大）｜去掉 M1 0.55–0.94｜去掉历史 0.79–0.97｜去掉报告 0.85–0.97。

### 4.7 误差分析

- 冻结测试中有 4/18 个场景的 top-1 不是最高分（F04-A，F10-A/B/C）。
- 全目录排序会让“内容含颈部”之类的内容先验主导无关用户（训练 / 推理不一致）→ 加入第一阶段检索（运行时 1.1.0）。

## 8. 尚未解决的问题

1. M2 没有人工标签：无法给出人工一致性、专家判断或真实用户层面的结论。
2. **近期练习超出训练范围**：首选章节 0–2 天内刚练过时模型弃权（合成场景的覆盖缺口）。活跃用户会经常遇到；修复需要在下一轮标注中加入近期练习场景。
3. 目标交叉特征无增益；历史、报告作用小；有历史时偏向衔接已练内容；报告主要重排所指章节。这些行为来自单一 AI 标注者，需要人工判断是否合理。
4. 只选“上肢”“下肢”等少数画像时低适配弃权（冷启动 8.7%）。
5. AI 标注者与 PR #49 的设计者为同一智能体，基线对照存在偏差风险（与 P0 的相关 ρ 0.445，与 PR #49 0.413）。
6. 测试集只有 6 个族；M1 只有单一示范者、4 套功法，太极拳泛化最弱。
7. 游戏没有姿态描述符，也没有历史记录持久化（游戏历史接口已就绪但无数据源）。
8. 报告分项的分数与趋势目前不是结构化字段，接入时传 null。
9. （2026-11-09 已处理）Web 正式页面已在 PR #53 接线并完成 E2E；SHADOW 实地验收只有 1 台设备，判为 INSUFFICIENT。原文：Web 正式页面尚未完成，接线、E2E 与 SHADOW 验收都还没有进行。现有独立预览页 `sprint/CoachSprint.tsx` 直接调用 `recommendCoach(profile, context)`，与引擎 OFF（只用画像的 P0）不完全相同（见 `WEB_INTEGRATION_READY.md` §1.1）。
10. 浏览器只在 Edge 上实测；性能只在开发笔记本上测过。
