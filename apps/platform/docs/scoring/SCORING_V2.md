# FormPilot Scoring v2 — Evidence-based & Explainable Evaluation

版本：`scoring-v2.0`（2026-09-28）　代码：`src/features/scoring/`　测试：`tests/scoring-v2-*.test.ts`、`tests/e2e/scoring-v2.spec.ts`

本轮目标：让每个分数都能回答“查的是什么、为什么查、在哪个动作阶段、测到多少、要求多少、依据是谁”。本轮**没有**修改任何实时纠错阈值、热身评分公式或权重；新增的是评分依据体系、跟练的动作规范检查，以及报告与 AI 教练的解释。

> 本体系是动作表现与跟练质量的参考，不是医学、康复或专业裁判评价；在没有真人与专家标注数据之前，不宣称达到专业裁判精度。

---

## 1. 评分哲学

1. **相似度 ≠ 动作质量。** “跟练相似度”只说明用户姿态与示范视频在同一时刻的视觉接近程度；“动作规范评价”检查具体技术要求（例如托举顶点时肘是否伸直）。两者分开计算、分开展示，本轮不合成总分。
2. **三层分离。**
   - Layer A 规范来源：什么叫做对——来自标准、官方动作规范、竞赛规则、学术研究或 FormPilot 示范（`sourceType` / `sourceId`）。
   - Layer B 可观测指标：单目摄像头 + 2D 姿态实际能测到什么（`observable` / `measurement`）。测不到的一律 `NOT_OBSERVABLE`，不伪造结果。
   - Layer C FormPilot 标定：偏离多少扣多少分（`target` / `tolerance`）。**所有数值阈值都是 `FORMPILOT_CALIBRATED`**，即使对应的要求来自官方，也从不把工程数值说成国家标准。
3. **知道边界是优点。** 报告明确列出“本项需要人工观察，目前不计入自动评分”的要求（呼吸、意念、眼神、手型、脚尖朝向、前后方向的脊柱形态等）。
4. **不越界。** 只评价可见姿态与跟练质量，不做受伤风险、关节疾病、康复或肌力的医学判断；AI 教练遇到疼痛/伤病问题直接拒答并建议就医。

## 3. Evidence Levels

| 等级 | 含义 | 规则（`tests/scoring-v2-registry.test.ts` 强制） |
|---|---|---|
| A | 官方标准 / 官方动作规范直接针对该动作的该项要求 | 来源类型只能是 OFFICIAL_STANDARD / OFFICIAL_GUIDANCE / COMPETITION_RULE |
| B | 国内同行评议研究、体育教材，或官方科学健身指导中的**一般性**原则（不针对该动作） | ACADEMIC_EVIDENCE 或 OFFICIAL_GUIDANCE |
| C | 只有 FormPilot 标准示范与工程标定 | 只能是 FORMPILOT_CALIBRATED |

证据等级描述“要求”的依据；数值阈值另有 `thresholdSource`（永远是 `FORMPILOT_CALIBRATED`）和 `thresholdBasis`（数值是怎么来的）。产品界面不显示 A/B/C，只显示来源名称，并把“动作要求依据……”与“数值阈值为 FormPilot 标定……”分两行写明。

## 4. 统一 Criterion Schema 与五种模式的评分结构

`EvaluationCriterion`（`src/features/scoring/types.ts`）字段：`id`、`mode`、`exercise`（热身动作 id 或跟练章节 id，`*` 表示全套）、`name`、`description`、`requirement`、`sourceType`、`sourceId`、`sourceTitle`、`additionalSourceIds`、`evidenceLevel`、`observable`（OBSERVABLE / PROXY / NOT_OBSERVABLE）、`scoring`（SCORED / ADVISORY / REFERENCE_ONLY）、`measurement`、`metric`、`landmarks`、`phase`、`target`、`tolerance`、`thresholdSource`、`thresholdBasis`、`weight`、`severity`、`feedback { issue, cue }`、`limitations`。

`measurement` 类型：
- `rep-component`：热身现有逐次评分的一个分项（metricKey + 原权重）；
- `rep-check`：热身的纠错/报告检查项，不占分；
- `guidance-metric`：肩部环绕（引导动作）的实时指标；
- `pose-window`：跟练检查——在标准视频姿态轨迹里找到的动作阶段窗口内，聚合用户的 2D 指标；
- `follow-along`：跟练比对本身的统计（太极节奏同步，仅参考）；
- `none`：只作规范参考。

| 模式 | 分数 | 结构 |
|---|---|---|
| 热身训练 | 综合评分 = 已完成计分动作的平均分（analysis-v1，未改）；动作分 = 各分项 × engineering-v1 权重 | 25 个计分分项 + 6 个提示项 + 4 个参考/不可观测项；肩部环绕为引导动作，只解释不计分 |
| 八段锦 | 跟练相似度（原有，未改）＋ 动作规范评价（新增，按权重平均） | 八式共 25 个计分检查、1 个提示检查、7 项待标定参考、14 项不可观测 |
| 五禽戏 | 同上 | 虎举、熊运、鸟飞 5 个计分检查；其余 7 动作以官方要点作参考 |
| 易筋经 | 同上 | 韦驮献杵一/二/三势与三盘落地 8 个计分检查；其余 8 势以官方肩髋错误解析作参考 |
| 太极拳 | 同上 | 全套 2 个计分（立身中正、屈膝步型）+ 2 个提示（虚实分明 estimatedWeightShift、演练节奏）|

## 5. 热身 6 动作 criteria

热身没有统一的“国家六动作评分标准”，因此**没有任何热身检查项标注 OFFICIAL_STANDARD**。界面表述统一为：动作规范参考国家体育主管部门公开科学健身指导和运动学原则，机器指标结合姿态评估研究与 FormPilot 标准示范进行量化。

每个计分分项的 `target` / `tolerance` 与 engineering-v1 评分函数逐项核对：单测用真实评分函数验证“达到 target 得 100、到 zeroAt 得 0”（复合分项验证剩余份额），并验证每个动作的分项、权重与现有代码一一对应、权重和为 1。

| 动作 | 检查（计分分项 · 权重） | 官方支持的部分 | FormPilot 标定的部分 |
|---|---|---|---|
| 肩部环绕（引导，不计分） | 活动幅度、双臂同步、动作连续、躯干稳定 | “热身应各关节全幅度活动、低强度”（热身运动你做对了吗，B） | 全部阈值（35°、0.55、0.55、10°） |
| 双臂上举 | 上举幅度 35%、手肘伸展 25%、双臂同步 20%、躯干稳定 10%、节奏 10% | 全幅度活动（B）、身体直立（侧平举指导的一般原则，B） | 90°→150° 曲线、110°→150° 肘角、4°/28°、3°/20°、2–4 秒 |
| 侧平举 | 侧举高度 35%、左右对称 25%、躯干稳定 20%、节奏 10%、完整完成 10%；手肘微屈（提示） | 身体直立、腰腹收紧（A）；手肘微屈（A，因此只把 <150° 视为明显屈肘）；侧举做法（B）；不耸肩（A，暂作参考） | 80–100° 带宽、5°/35°、3°/20°、2–4 秒 + 顶部停留 |
| 侧步开合 | 手脚协调 30%、开合幅度 25%、节奏 20%、身体稳定 15%、回到中间 10%；左右交替（提示） | 无直接国内动作标准（全民健身指南仅作强度与安全背景） | 全部阈值 |
| 徒手深蹲 | 下蹲幅度 30%、左右均衡与躯干 25%、膝部轨迹（不内扣）20%、完整起立 15%、节奏 10% | 大腿接近与地面平行、并非越深越好（A）；膝盖不内扣、与脚尖方向一致（A）；重心在两腿中间（B） | 髋部下降曲线（0.35 封顶，更深不加分）、膝距/髋宽 0.92/0.55、膝高差 0.03/0.16、3–5 秒 |
| 交替提膝 | 提膝高度 30%、支撑稳定 25%、左右交替 20%、左右对称 15%、节奏 10% | 无（不声称任何官方绝对高度） | 全部阈值 |

深蹲的“腰背挺直、骨盆中立”“脚尖外开不超过 30°”“收紧核心”为 NOT_OBSERVABLE（正面 2D 看不到前后方向与脚尖朝向）。

## 6. 八段锦 criteria

八段锦检查项优先由官方《习惯性错误及纠正方法》转化。阶段窗口取自标准视频自身的姿态轨迹（视频就是时钟）：例如第一式“托举顶点”= 示范者双腕高出鼻尖 ≥0.45 躯干长且两臂张开 ≥160° 持续 ≥1 秒，标准视频中恰好检出 6 次托举。

### 6.1 第一式 · 两手托天理三焦（样板）：官方要求 → 可测指标 → 阈值 → 分数 → 反馈

| 官方要求（习惯性错误 / 纠正） | 机器指标（阶段：托举顶点） | 阈值（FormPilot 标定 · 依据） | 权重 | 扣分原因 → 纠正提示 |
|---|---|---|---|---|
| 错误三：上举不充分，两臂未伸直；纠正：两肘慢慢伸直、继续伸直上托 | 肘角（较弯一侧），窗口内 75 分位 | ≥150° 满分，120° 为 0；示范者 6 次中位 154–158° | 3 | 托举顶部两肘未伸直 → 抬头看手上举时，两肘慢慢伸直，两臂继续伸直上托 |
| 错误二：两臂向前倾斜过大；错误三：上举充分，两掌至头顶正上方 | 双腕高出头部（躯干长，较低一侧），75 分位 | ≥0.45 满分，0.1 为 0；示范 0.62–0.67 | 3 | 托举不够充分 → 两掌继续上托，移至头顶正上方（前倾只能间接体现，PROXY） |
| 纠正：两臂帖耳 | 上臂偏离竖直（较外展一侧），中位数 | ≤15° 满分，40° 为 0；示范 3–7° | 2 | 托举时两臂向外张开 → 两臂向耳侧收拢 |
| 两掌同时上托（示范动作本身，证据 C） | 左右肩角差 | ≤10°，30° 为 0；示范 1–3° | 1 | 两臂高低不一 → 两掌同时上托 |
| 立身中正（团体标准） | 躯干侧倾 | ≤8°，20° 为 0；示范 1–2° | 1 | 身体侧倾 → 头正身直 |
| 动作连贯（轻量：阶段完成） | 每次托举是否达到双腕高出头部 0.2 躯干长 | 按次计完成率 | 1 | 有几次托举没有跟上 → 跟着口令完成每一次上托和下落 |
| 错误一：先抬头后上举（眼随手走） | — | NOT_OBSERVABLE（目视与抬头时机） | 0 | — |
| 错误四：分手时猛力拉开 | 可用手腕速度估计 | 参考项：需真人数据标定速度阈值 | 0 | — |

用户跟练落后 ≤1 秒或以镜像方式跟练时，窗口向后延长 1 秒（不超过本段结束）且所有指标左右对称定义，示范自身跟练仍全部满分（单测）；肘部被弯曲 45° 的扰动会使该项扣分，证据形如“第 4 次托举顶点（视频 01:36）双肘伸展角（较弯一侧） 131°，要求 ≥ 150°”。

### 6.2 其余七式（每式 2–4 个计分检查，完整见附录 B）

- 第二式：屈膝成正马步（膝角 ≤155°，不奖励更低）、重心居中（estimatedWeightShift ≤0.3，防偏马步）、推弓手与拉弓手同高（两腕高度差 ≤0.2）、正身；手型与拉弓手路线为不可观测 / 参考。
- 第三式：上举手撑举到位、上举手不偏侧（“偏前”不可见）、下按手按至胯旁、身体中正；掌心平托与中指尖路线为不可观测 / 参考。
- 第四式：转头后瞧（鼻尖偏移估计）、两臂稍侧开约 45°（官方给出约 45°，二维示范实测 52–58°，取 35–70°）、躯干正直；两眼水平为提示项（眼点噪声大）；旋臂为不可观测。
- 第五式：马步蹲坐、俯身不过大（头部不低到髋部高度）；“臀部高度不变”尝试后降为参考项——示范者本身髋高波动 0.2–0.6 躯干长，二维指标无法区分，诚实地不进入评分；颈腰放松、眼看脚尖不可观测。
- 第六式：以臂带身、帖耳起身（俯身前伸阶段臂与躯干夹角 ≥150°）、起身后两臂上举；摩运时低头不可观测，腋下后插位置为参考。
- 第七式：马步稳定、重心居中（证据 C）、上体正直；冲拳“肘部自然直”因拳朝镜头透视不可靠、怒目与握固均不可观测。
- 第八式：起落时身体中正（只看左右晃动）；提踵高度为参考，前后重心移动不可观测。

## 7. 五禽戏 criteria

计分：虎举（两掌上举到位、头身正直）、熊运（相对固定腰胯：髋中心每 8 秒波动 ≤0.4 髋宽——直接来自官方“以腰胯为轴转动或摇晃幅度过大 → 相对固定腰胯”）、鸟飞（提膝独立、独立平衡）。其余七动作（虎扑、鹿抵、鹿奔、熊晃、猿提、猿摘、鸟伸）列出官方要点，标注“动作规范参考，目前不进入视觉评分”及原因（多为前后方向的脊柱形态、目视、需要真人标定）。全套不可观测：五禽神韵、呼吸、五禽手型、步法中膝盖与脚尖方向一致。

## 8. 易筋经 criteria

计分：韦驮献杵第一势（合掌时沉肩坠肘：两臂张开 ≤40°，对应“耸肩抬肘”）、第二势（两臂侧举呈水平：两腕偏离肩高 ≤0.2 躯干长，对应“两臂侧举不呈水平”；立掌外撑）、第三势（两掌上托于头顶、上托时避免屈肘）、三盘落地（逐步下蹲充分：每次膝角 ≤150°，不要求达到示范者的全蹲；两膝不过度内合或外展：两膝/两踝间距 0.65–1.15；上体中正）。摘星换斗、倒拽九牛尾、出爪亮翅、九鬼拔马刀、青龙探爪、卧虎扑食、打躬、掉尾均按官方肩髋错误解析列为参考。全套不可观测：呼吸自然、用力适度、意识专一。

## 9. 太极拳 criteria

借鉴竞赛规则“动作质量 / 演练水平”分开的思路，但不照搬扣分表与总分。
- 动作质量（计分）：立身中正（示范立身定势时用户躯干侧倾 ≤10°）、屈膝步型（示范屈膝时用户较弯一侧膝角 ≤160°，架子高低量力而行）。
- 虚实分明（提示）：`estimatedWeightShift`——基于髋、膝、踝与身体中心投影的**视觉估计**，不是足底压力，不等同于真正的“虚实”，只提示不计分。
- 演练水平·节奏（提示）：沿用跟练比对的节奏同步占比，明确标注它属于相似度的一部分。
- 重心高度平稳为参考项（转体投影误差大，待真人标定）；松沉劲整、手型、眼神、呼吸不可观测。
- 3D / MotionBERT 与 DTW 不在本轮实现；接口上为后续 `temporalAlignmentScore` 预留（技术记录按阶段窗口保存，可直接替换为时序对齐后的窗口）。

## 10. Observable vs Not Observable

统计（与 registry 同步生成）：热身 35 项（计分 25 / 提示 6 / 参考 1 / NOT_OBSERVABLE 3）；八段锦 47 项（25 / 1 / 7 / 14）；五禽戏 17 项（5 / 0 / 7 / 5）；易筋经 19 项（8 / 0 / 8 / 3）；太极拳 9 项（2 / 2 / 1 / 4）。

被判定 NOT_OBSERVABLE 的官方要求（全部不计分，报告显示“本项需要人工观察”）：呼吸配合、意念/神态/神韵/意识、眼神与目视方向（八段锦第一式眼随手走、第五式眼看脚、第七式怒目）、手型（八字掌、拉弓爪、虎爪、握固、五禽手型、太极掌拳勾）、手臂旋转与掌心朝向（第三式平托、第四式旋臂）、冲拳肘部自然直（透视）、颈腰放松与头尾三维摆动、摩运时低头、前后方向的重心移动、深蹲腰背与骨盆、脚尖朝向、核心收紧、用力适度、松沉劲整。

PROXY（间接估计）检查项在 limitations 中写明局限，例如“前倾只能通过手腕高度降低间接反映”“只能看到左右侧倾”。

## 11. 工程阈值如何标记

- 所有带 `target` 的检查项 `thresholdSource = 'FORMPILOT_CALIBRATED'`，`thresholdBasis` 写明来源：热身 = engineering-v1（真人测试修正，尚未经专家标注）；跟练 = 标准示范实测值 + 余量（示范者的数值列在每项里）。
- 标定规则：跟练阈值必须让标准示范自身在全部窗口得满分（单测逐套验证），再按“明显偏离才扣分”留出余量；涉及下蹲/马步/提膝的阈值只要求“明显做到”，不奖励更低更深。
- 官方给出数字的地方（八段锦第四式“约 45°”）也不直接作为阈值：二维测量口径不同，按示范实测改为区间并在 basis 中说明。

### 现有评分规则的判断（本轮只判断，不改动）

| 规则 | 结论 |
|---|---|
| 深蹲膝内扣（膝距/髋宽）、下蹲幅度（封顶）、侧平举躯干直立 | 有官方依据，保留；阈值待真人标定 |
| 双臂上举“手肘伸展”分项 | 有依据但口径需重新标定：分项取整次最小肘角，而实时纠错与报告问题只看顶点肘角（<135°，已真人修正） |
| 深蹲“对称性”分项 | 有依据但命名不准：实际是膝内扣代理指标，建议下个版本把报告标签改为“膝部方向” |
| 侧平举手肘 | 与官方“手肘微屈”一致（只提示 <150°），保留为不计分提示 |
| 侧步开合、交替提膝全部阈值、各动作节奏区间 | 工程经验（证据 C），保留，待真人数据校准 |
| 应删除的规则 | 本轮未发现必须删除的规则；八段锦“臀部高度不变”的二维候选指标在设计阶段因示范者自身不达标而未启用 |

## 12. 后续真人 / 专家校准计划

1. 采集：每套功法 ≥10 名受试者（覆盖初学者与熟练者、不同年龄与体型），同时录制正面摄像头与侧面参考视频；热身 6 动作同样采集。
2. 专家标注：由健身气功社会体育指导员 / 太极拳教练逐阶段标注“达标 / 轻微偏差 / 明显错误”，并标注被判定为不可观测的要求，用于确认它们是否确实无法从正面 2D 判断。
3. 校准：以专家标注为金标准拟合每个检查项的 target 与 tolerance（ROC / 一致性 κ），检查项的敏感度、特异度写入 `thresholdBasis`；证据不足的检查项降为提示或参考。
4. 版本：阈值变化即发布 `scoring-v2.x`，旧记录按其保存的 `technique.version` 解读；热身沿用 `createCalibrationThresholdProposal` 生成 calibration-v1 提案，经 analysis-v2 评估后启用。
5. 后续升级：DTW 时序对齐（`temporalAlignmentScore`）、轨迹平滑度、提踵与重心高度的基线标定、耸肩检测、侧面机位。

## 13. 数据与接口

- 跟练技术证据保存在 `formpilot.routine-sessions:v1` 记录的可选字段 `technique`（`version`、每个检查项×章节的窗口 `{start, end, samples, value, score}`）。旧记录没有该字段，报告显示原因，不补算。
- 肩部环绕在 `ai-coach.sessions:v2` 的 `ExerciseSessionResult.guidanceSummary` 中保存环绕过程的指标均值与提示帧数，不进入任何分数；analysis-v1 不读取它。
- 热身解释只读已保存的逐次数据（每次的原始字段与分项分），与报告显示的 analysis-v1 动作分一致（单测核对）。
- AI 教练：报告摘要新增 `scoreExplanation`（分项、主要扣分及测量值与阶段、依据）；新问题“为什么是这个分数？”；实时“为什么提示我”会说明对应的检查项，跟练提示会说明它是相似度提示而非规范扣分。
