# E5 · 动作工坊产品闭环验收

## 闭环与兼容性

| 环节 | 验证 | 结果 |
| --- | --- | --- |
| 创建、编辑、保存 | 浏览器从空白创建动作，录制两端姿势，测试通过后保存；重新加载并编辑同一动作 | 通过 |
| 正式训练、计次、实时反馈 | 保存后进入训练；使用开发用合成姿态完成 3/3 次，反馈区域可见 | 通过 |
| 持续时间 | 创建 5 秒保持动作，在完成姿势持续保持，训练自动结束；报告显示 5/5 秒 | 通过 |
| 报告与历史 | 报告可由完成页打开；模拟的真实来源记录出现在历史页并可回到报告 | 通过；合成来源记录按设计不进入历史 |
| 旧动作库 | 导入旧版动作后可打开训练；旧库原数据不改写，刷新后也不再重复提示导入 | 通过 |

主要浏览器用例：`tests/e2e/workshop.spec.ts` 中 A、D、H、H2。测试使用开发用合成姿态；历史页只接受 `source: live`，所以 H/H2 在检查合成记录被排除之后，显式复制一条模拟真实来源记录，验证历史页的读取和报告链接。该步骤不能替代真人摄像头验收。浏览器用例 G 另外检查真实视频流进入 MediaPipe Full 管线，并确认既有热身训练继续使用 Lite 模型。

自定义动作记录使用独立的 `formpilot.custom-action-sessions:v1` 存储；旧动作库保留在原 key 中。未知新版本动作数据维持只读，防止旧客户端覆盖。动作训练报告不混入热身训练的分数或五维指标。

## 性能与构建

`tests/workshop-performance.test.ts` 使用同一组侧平举合成关键点，将 1000 帧送入姿态归一化和正式识别器；前 100 帧预热后记录 900 帧耗时。2026-11-11 本机 Node 运行：P50 **0.006 ms/帧**、P95 **0.016 ms/帧**，计得 11 次。该数字不含摄像头解码、MediaPipe 推理、浏览器绘制和低端设备影响，不能据此声称端到端实时性能。

生产构建通过。构建器提示主入口压缩前约 883 kB，超过其 500 kB 提示线；这是后续拆包优化点，本次没有改变现有入口结构。

工坊相关单元测试共 60 项通过；`typecheck`、`lint`、`build` 均通过。另尝试仓库级单元测试，结果为 112 个文件通过、8 个文件失败、1 个文件跳过（1754 项通过、149 项失败、5 项跳过）。失败包括此稀疏检出缺少的 EXE 图标文件，以及当前执行环境无法访问的本地 HTTP 回环服务；因此不把仓库级测试记为通过。工坊测试文件均通过。

动作工坊与本地视频的 Edge 浏览器回归共 12 条通过；删除场景单独复测也通过。

## 已知边界

- 本轮自动闭环测试主要使用合成姿态和本地视频流。仍需在常见摄像头、光照、遮挡、不同身材与真实动作上做人工验收，特别是误计、漏计、反馈延迟和连续保持。
- 本地视频能否解码取决于浏览器实际支持的编码；界面不按扩展名预拒绝，但无法解码时会提示用户换视频或改用摄像头。
- E3 的连续示范基础版与 E4 的三阶段识别实验是不同成熟度的能力：三阶段原型尚未接入正式动作定义和训练，不能当作产品功能使用。
- E4 短遮挡恢复的 150 ms、0.3 进度阈值来自合成关键点对照，需真实视频校准；对照细节见 `E4_TEMPORAL_COMPARISON.md`。
- 动作与训练记录在浏览器本地存储，不会跨设备自动同步；用户清除网站数据后也无法从服务端恢复。

## 本轮复核命令

在 `apps/platform` 下运行：`pnpm typecheck`、`pnpm lint`、`pnpm build`、`pnpm exec vitest run workshop`、`pnpm exec playwright test tests/e2e/workshop.spec.ts tests/e2e/workshop-video.spec.ts`。浏览器测试配置改用与仓库说明和 CI 一致的 `pnpm dev` 启动应用。
